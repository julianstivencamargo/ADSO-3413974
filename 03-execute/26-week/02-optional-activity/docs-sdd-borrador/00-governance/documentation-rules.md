# Reglas de documentación

- La documentación se escribe en español y conserva los nombres técnicos del código.
- Cada documento responde una sola pregunta.
- Los datos deben provenir del código, `db/schema.sql`, pruebas o una decisión aprobada.
- Toda afirmación de comportamiento debe poder comprobarse.
- Los enlaces internos son relativos.
- El estado de cada función se marca como `Implementado`, `Parcial` o `Pendiente`.
- Un documento pasa de borrador a aprobado después de revisión de una segunda persona.
- Un cambio de código actualiza en el mismo pull request el documento relacionado.
